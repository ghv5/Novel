# 01 · 架构总览：一个 Coding Agent 的 Monorepo 解剖

> Pi 是一个用 TypeScript 编写的生产级 Coding Agent 框架，采用 npm workspace monorepo 组织。
> 本文从顶层视角拆解 12 个包的职责与分层协作关系。

## 1.1 项目定位

Pi 是 [pi.dev](https://pi.dev) 开源项目，核心产品是 `@earendil-works/pi-coding-agent` —— 一个自扩展的终端编码智能体。它支持四种运行模式：

- **interactive**：交互式 TUI（终端 UI）
- **print / JSON**：单次执行输出结果或 JSON 事件流
- **RPC**：进程间通信集成
- **SDK**：嵌入其他应用

## 1.2 包清单与职责

| 包 | npm 名 | 职责 |
|----|--------|------|
| `packages/agent` | `@earendil-works/pi-agent-core` | **Agent 运行时核心**：tool calling 循环、状态管理、会话/压缩/事件 |
| `packages/ai` | `@earendil-works/pi-ai` | **统一多 Provider LLM API**：归一化 OpenAI/Anthropic/Google 等 30+ 提供商 |
| `packages/coding-agent` | `@earendil-works/pi-coding-agent` | **交互式编码 CLI**（本仓库主体）：内置工具、会话管理、TUI |
| `packages/tui` | `@earendil-works/pi-tui` | 终端 UI 库，差分渲染 |
| `packages/chord` | `@earendil-works/chord` | 独立应用组合运行时（services、replicated state、RPC、plugins） |
| `packages/durable` | `@earendil-works/pi-durable` | 持久化 conversation / task / document 运行时 |
| `packages/telemetry` | `@earendil-works/pi-telemetry` | 厂商中立遥测契约 + 参考 adapter |
| `packages/protocol` | — | RPC 通信协议（CBOR 序列化 / framing） |
| `packages/client` | — | RPC 客户端 |
| `packages/server` | — | RPC 服务端 |
| `packages/evals` | — | 评测框架 |
| `packages/session-backends` | — | 会话后端（SQLite 等，核心 agent 包不默认拉取） |

## 1.3 分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  coding-agent (CLI / interactive / print / rpc / SDK)           │
│    AgentSession: 会话核心，桥接 UI 与 runtime                    │
│    内置工具: read/write/edit/bash/powershell/grep/find/ls        │
│    扩展: extensions / skills / prompt-templates                  │
├─────────────────────────────────────────────────────────────────┤
│  agent (pi-agent-core)                                          │
│    Agent 类（有状态包装器）                                      │
│    runLoop（无状态双层 while 主循环）                             │
│    harness/: tools / session / compaction / events / runtime    │
├─────────────────────────────────────────────────────────────────┤
│  ai (pi-ai)                                                     │
│    Provider 工厂(30+) → API 协议实现(10种) → 统一事件流          │
│    统一类型: Message / ToolCall / AssistantMessageEvent          │
├─────────────────────────────────────────────────────────────────┤
│  周边: tui / chord / telemetry / durable / protocol / client    │
└─────────────────────────────────────────────────────────────────┘
```

**依赖方向**（从 `package.json` 的 `build` script 构建顺序可见）：

```
chord → tui → telemetry → ai → durable → agent → session-backends → protocol → client → server → coding-agent
```

## 1.4 启动链路

```
cli.ts (7 行)
  → setupCli() + main(process.argv.slice(2))
  → main.ts: 解析 CLI 参数
  → agent-session-services.ts / agent-session-runtime.ts: 创建 AgentSession
  → sdk.ts: setDefaultStreamFn(streamSimple) + createAgentSession()
  → AgentSession: 共享所有运行模式的核心
```

**关键解耦点**：
- `cli.ts` 仅 7 行，只做参数解析和入口分发
- `sdk.ts` 是 SDK 嵌入入口，通过 `setDefaultStreamFn` 把 LLM 调用绑定到 `pi-ai` 的 `streamSimple`
- `AgentSession` 是四种运行模式共享的会话核心，封装：Agent 状态访问 / 事件订阅 / 模型管理 / 压缩 / bash 执行 / 会话切换与分支

## 1.5 配置与约定

- **配置目录**：`.pi/`（`piConfig.configDir`），含 `skills/`、`prompts/`、`extensions/`、`git/`、`npm/`
- **供应链加固**：依赖精确 pin + `.npmrc save-exact` + `min-release-age=2` + `package-lock.json` 为准 + 发布包内置 `npm-shrinkwrap.json` + `--ignore-scripts` 安装策略
- **权限模型**：Pi 不内置权限系统，以启动用户权限运行；强隔离靠容器化（Gondolin micro-VM / Docker / OpenShell）

## 1.6 内置工具清单

`packages/coding-agent/src/core/tools/` 下 8 个内置工具：

| 工具 | 文件 | 功能 |
|------|------|------|
| `read` | `read.ts` | 读文件（文本/图片/二进制，截断保护） |
| `write` | `write.ts` | 写文件（创建/覆盖） |
| `edit` | `edit.ts` + `edit-diff.ts` | 精确文本替换编辑 |
| `bash` | `bash.ts` | 执行 shell 命令 |
| `powershell` | `powershell.ts` | 执行 PowerShell 命令 |
| `grep` | `grep.ts` | 正则搜索文件内容 |
| `find` | `find.ts` | 按 glob 搜索文件 |
| `ls` | `ls.ts` | 列目录 |

辅助模块：`file-mutation-queue.ts`（并发写序列化）、`path-utils.ts`（路径解析）、`truncate.ts`（输出截断）、`output-accumulator.ts`（输出累积）、`renderers/`（TUI 渲染器）。

## 1.7 核心设计决策

| 决策 | 原因 |
|------|------|
| 12 包 monorepo | 职责清晰：核心循环 / LLM 层 / CLI / TUI / 持久化各自独立演进 |
| 无状态循环 + 有状态包装器 | 循环可独立测试，状态由 Agent 类管理 |
| LLM 调用完全解耦到 pi-ai | agent 包不依赖任何具体 provider，通过 `StreamFn` 注入 |
| 内置工具可插拔（Operations 接口） | 支持 SSH / 远程执行等替代实现 |
| 供应链加固 | 生产级安全：pin + shrinkwrap + ignore-scripts |
