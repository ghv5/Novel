# 10 终端界面与交互：主屏 / 备用屏与约束布局系统

> 前九篇讲的是"逻辑"。这一篇讲"呈现"：Pi 如何在终端里既保留可滚动的历史，又让输入区/状态区固定不动。
> 主要文档：`pi/tui-plan.md`（布局系统设计手稿）、`packages/coding-agent/docs/tui.md`（组件 API）、`packages/tui/`。
> 基于 0.87.0。

## 10.1 两种终端模式的根本差异

【设计取舍】终端编程里最关键的一个分叉是**主屏（main screen）** vs **备用屏（alt screen）**：

- **主屏**：内容写进终端自身的 scrollback，滚动由**终端**负责。应用无法可靠地做 sticky 行、嵌套独立滚动区、全高并排面板、对已进入 scrollback 的内容做命中测试。
- **备用屏**：应用接管整屏，每帧自己绘制。可以自由布局，但必须自己处理滚动、裁剪、光标、选区。

Pi 的结论（`tui-plan.md §Core decisions`）：**不要假装两种模式有相同的视口语义**。主屏保持"竖排文档"，备用屏才用约束布局。

```
主屏（终端负责滚动）              备用屏（应用负责绘制）
┌──────────────────┐            ┌─────────────────────────────┐
│ header           │            │ 可滚动 transcript            │
│ loaded resources │            │  header / chat / tools      │
│ chat             │            ├─────────────────────────────┤
│ pending          │            │ 固定 dock：                  │
│ status           │            │  pending / status / widgets  │
│ widgets above    │            │  editor / footer             │
│ editor           │            └─────────────────────────────┘
│ widgets below    │
│ footer           │
└──────────────────┘
```

【设计取舍，很重要】"pending 消息"和"status"放在**固定区**而不是 transcript 里。理由很人性化：用户在往上翻历史时，**不应该看不到"Agent 还在工作/还有排队消息"**。

## 10.2 组件模型

【代码事实】所有组件实现 `Component`（`tui.md §Component Interface`）：

```typescript
interface Component {
  render(width: number): string[];          // 每行不得超过 width
  handleInput?(data: string): void;          // 获得焦点时收键盘
  handleMouse?(event): TuiMouseEventResult | undefined;
  wantsKeyRelease?: boolean;                 // 默认 false
  invalidate(): void;                        // 主题变化时清缓存
}
```

【坑，原文强调】TUI 在**每行末尾**追加 SGR reset + OSC 8 reset，**样式不跨行**。所以多行带色文本必须逐行重新应用样式，或用 `wrapTextWithAnsi()`。

需要文本光标 + 输入法（IME）支持的组件实现 `Focusable`：焦点时在光标处发出零宽 `CURSOR_MARKER`，TUI 扫描后把**硬件光标**移到那里（硬件光标默认隐藏，靠 `showHardwareCursor`/`PI_HARDWARE_CURSOR=1` 打开）。

【坑，中文用户必看】容器组件（dialog/selector）里嵌了 `Input`/`Editor` 时，**容器必须实现 `Focusable` 并把焦点状态透传给子组件**，否则中日韩输入法的候选框会出现在屏幕错误位置。文档专门给了 `SearchDialog` 的例子。

## 10.3 备用屏布局原语：VStack / HStack / ScrollView

【代码事实】`tui-plan.md §Public API` 定义了三个公开原语，一个轴无关的 `StackEntryOptions`：

```typescript
interface StackEntryOptions {
  basis?: number | "auto";   // 主轴初始尺寸，默认 auto
  grow?: number;             // 分正剩余空间，默认 0
  shrink?: number;           // 溢出时收缩意愿，默认 1
  minSize?: number;          // 最小分配，默认 0
  maxSize?: number;
  visible?: (viewport) => boolean;
}
```

- `VStack`：自上而下；`gap` 只在**可见子项之间**出现；交叉轴默认 `stretch`。
- `HStack`：自左向右；宽度先分配再测量高度；必须用 ANSI 感知的切片/合成工具，**绝不能用 `string.length` 或裸 substring**（CJK/emoji 一个字符可能占 2 列）。
- `ScrollView`：核心选项 `follow: "none" | "end"`、`primary`、`overscroll: "chain" | "contain"`。`scrollBy()` **返回未消费的 delta**，用于嵌套滚动链。

【设计取舍】约束布局（constrainted layout）是**备用屏专属能力**，通过一个显式能力接口暴露：

```typescript
interface ViewportTUI extends TUI { setLayoutRoot(component: Component | undefined): void; }
export function isViewportTUI(tui: TUI): tui is ViewportTUI;
```

`TuiAltScreen` 实现它，`TuiMainScreen` 不实现。类型守卫应基于**稳定能力**（symbol / 方法存在性），而不是应用层的 `instanceof`。这样主屏永远不会被塞进它并不支持的视口语义。

## 10.4 组件树 vs 布局树：每帧重建几何、复用叶子渲染

【设计取舍，核心】Pi 明确区分两棵树：

```
公开组件树（长期、有状态）           内部布局树（每帧瞬时快照）
VStack                              box root       rect 0,0,120,40
├─ ScrollView                       ├─ scroll box  rect 0,0,120,31 clip 0,0,120,31
│  └─ chat container                │  └─ content  rect 0,-85,120,116
└─ dock VStack                      └─ dock box    rect 0,31,120,9
   ├─ editor container
   └─ footer container
```

规则（`§Core decisions`）：

1. **每帧重建布局树，但绝不重建组件状态**（例外：`ScrollView` 的有意 clamp/follow 状态）。
2. 叶子渲染**复用已有缓存**：`Markdown`/`Text`/`Image`/`Box` 都按内容 + 宽度缓存渲染行；布局 box 只是**按引用**保留这些行数组，不复制。
3. **不要引入第二套框架级渲染缓存**（如 `WeakMap<Component, RenderCache>`）——现有组件自己拥有失效语义，第二套缓存会变陈旧。
4. **没有 render 请求就没有布局**：布局帧只在 `requestRender()` 调度后重建，没有独立布局循环。
5. 每帧结束后**原子替换**已提交帧，保证输入永远路由到"上一次真正显示出来的几何"。

【给新项目】"几何每帧重建、像素/字符串复用缓存"是终端 UI 性能的关键：布局计算很便宜，重排 + ANSI 合成才贵。把这两者分开，才能既正确又快。

## 10.5 输入路由：命中测试、滚轮链、键盘回退

【代码事实】

- **命中测试**针对**已提交帧**（不是正在构造的帧）：先剔除非裁剪区内的 box，再从高层/最前子项遍历，返回包含坐标的**最深可见 box**，并保留祖先链用于事件冒泡。
- **滚轮路由**：在最深 box 开始向根走，把 delta 依次交给遇到的每个 `ScrollView`；`overscroll: "chain"` 把剩余 delta 传给下一个滚动祖先，`"contain"` 就地停止；若没有祖先消费，则交给帧的 `primary` 滚动视图；最后**必须消费掉已识别的鼠标序列**，防止裸鼠标字节进到编辑器。
- **键盘永远可用**：不依赖"检测鼠标是否支持"（终端没有可靠的能力信号）。方向键/翻页绑定 `tui.altScreen.pageUp/pageDown/top/bottom`，目标永远是 primary 滚动视图（未来多面板时先看"显式激活的滚动区"）。
- **触控板**：垂直滚动视图忽略水平 delta；双轴事件只消费垂直部分。

【设计取舍】"焦点"和"滚动目标"是**两个独立概念**：滚一个侧边栏不能把键盘焦点从编辑器拿走。

## 10.6 焦点、光标、选区与超链接

【代码事实】

- `TUI.setFocus(component)` 仍是公开的键盘焦点 API。
- 绘制时在**最终合成帧**里找 `CURSOR_MARKER`；光标行列要计入 stack 偏移、滚动平移、overlay 偏移、水平面板偏移。
- **选区**：锚点/焦点从终端屏幕坐标出发，对当前已提交可见帧做高亮，复制时用 ANSI 感知切片 + `stripTerminalSequences()`；空白/填充区域除必要的行分隔外不产生文本；列仍按字素边界吸附。
- **超链接**：从已提交屏幕行对应列读 OSC 8 元数据——必须用**最终合成行**，而不是未平移的子行。行为保持：点击不拖动可 `openUrl`，拖动不触发链接，拖后释放走 OSC 52 复制。

【坑】旧 alt 渲染器假设"选区行 = 一个全局逻辑文档的一行"。一旦有了固定区和水平面板，这个假设失效。I 期保留"可见屏选区语义"，并明确**不要把固定 dock 的行映射到不相关的 transcript 行**。

## 10.7 覆盖层（overlays）与图片

【代码事实】

- **Overlays 保持现有堆叠/定位 API**：先把约束布局画成"终端高度"的行，再用现有 overlay 逻辑合成，然后提取光标、做差分渲染。overlay 不要求变成嵌套 `ScrollView` 根，但基础布局的命中测试**不能破坏 overlay 的焦点/输入归属**。
- **图片**：I 期只需保住"垂直滚动 transcript"这一种场景（Kitty 图片元数据与预留行、顶部被滚出视口时裁剪、行变化时删除/重绘、iTerm2 回退）。**水平拼接图片协议行不要求通用化**——图片 placement 不像普通 ANSI 文本；文档要求"防御性处理并加聚焦测试"，不能悄悄搞坏相邻面板。

## 10.8 踩坑与设计取舍

| 坑 | 对策 |
|----|------|
| 主屏假装支持 sticky/嵌套滚动 | 用 `ViewportTUI` 能力接口把约束布局限定在备用屏 |
| 每帧重建组件状态 | 只重建**布局几何**；叶子渲染按引用复用缓存 |
| 用字符串长度算终端列宽 | 一律用 ANSI 感知的 `sliceByColumn`/`compositeTuiLine`/`visibleWidth`/`wrapTextWithAnsi` |
| 水平相邻子项样式串色 | 每段之间插 reset 边界；OSC 8 超链接同理 |
| 尺寸分配抖动 | 整数取整必须**确定性**；剩余 cell 按子项顺序分配 |
| CJK/emoji/组合字符裁剪 | 聚焦测试覆盖字素边界 |
| 裸鼠标字节进编辑器 | 路由后消费掉已识别序列 |
| 退出备用屏只打印最后一帧 | 退出时用**无界高度**重渲根，打印完整逻辑文档，且不打印终端高度填充行 |

## 10.9 验证清单

【代码事实，来自 `tui-plan.md §Test plan`】布局系统自带一份很完整的验收矩阵，可直接当检查表：

- **栈分配**：auto/numeric basis、grow/shrink、min/max、奇数取整确定性、gap 只在可见子项间、跨轴对齐、超宽裁剪、ANSI 不串色、CJK/emoji 边界。
- **ScrollView**：初始 `follow:end`、跟随增长、手动上滚关闭 follow、到底重新 follow、`scrollBy` 返回剩余 delta、嵌套链、`contain`、空/短子项、视口变化、聚焦内容被裁剪时光标仍可见。
- **布局帧**：嵌套矩形、累积裁剪、命中测试最深可见 box、裁剪 box 不可命中、局部坐标、层序、只画可见行、resize 后新几何、缓存行按引用且不被修改。
- **渲染器**：legacy `addChild()` 路径不回归、固定 dock 不动、transcript 视口高度扣掉 dock、键盘/滚轮目标、光标行列正确、overlay 合成、OSC 8 点击、选区复制、resize、超宽 dock 不丢光标、退出打印完整文档一次。
- **主屏回归**：所有既有测试通过、子项顺序/输出不变、不安装布局根。

## 10.10 给新项目的建议

1. **先决定主屏还是备用屏**，不要试图用一套渲染同时满足两种滚动语义。
2. 备用屏用**三原语**（VStack/HStack/ScrollView）+ 轴无关的 stack entry 参数起步，别一上来做 flexbox/grid。
3. **几何与缓存分离**：每帧重建布局树，叶子渲染复用已有缓存。
4. **能力接口而非 `instanceof`**：让"支持约束布局"成为显式能力。
5. **滚轮链 + 键盘回退**：鼠标是增强，键盘是保底。
6. **把切换模式时的完整文档打印**当成一等公民，否则用户退出后看到的是残缺历史。
