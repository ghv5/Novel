# SpringCloud Alibaba 电商项目实战经验 - 场景索引

本系列把 `shop-springcloud-alibaba` 当作一个端到端的微服务工程案例，按“一次完整业务目标 + 失败模型”组织成若干场景文章，回答“以后做同类微服务怎么选、怎么落地、会踩什么坑、如何验证”。这不是框架入门或逐文件源码讲解。

> 存放说明：本仓库所在磁盘为网络共享（Mac SMB）挂载，实测无法在该共享上创建新目录，因此本系列直接输出到 `docs/` 目录，而非默认的 `docs/项目实战经验/`。`docs/nacos/` 为项目原有内容（Nacos 配置导出），与本系列无关。

### 依赖版本的两处不一致（需注意）

- 根 `pom.xml` 的 `parent` 声明 Spring Boot `2.2.6.RELEASE`（第 8 行），但 `dependencyManagement` 导入 `2.3.12.RELEASE`（第 39-45 行），`properties` 的 `spring.boot.version` 也是 `2.3.12.RELEASE`（第 19 行）。实际生效以导入的 BOM 为准，`parent` 行形同摆设。
- 全局 `mybatis-plus.global-config.db-config.id-type: auto`（Nacos `server-all.yaml`）与实体 `@TableId(type=IdType.INPUT)`（`shop-bean/.../Order.java:23`）语义相反，注解覆盖全局。

## 核心工程发现速览

以下是本次静态分析中由代码/配置交叉证实、对“资深工程师”最有价值的发现。每条都能在对应文章中找到定位证据。

| # | 发现 | 性质 | 关联文档 |
|---|---|---|---|
| 1 | `OrderParams.isEmpty()` 把 `userId <= 0` 误写成 `productId <= 0`，用户 ID 非法值能通过校验 | 已证实缺陷 | 接口契约 |
| 2 | 全局异常处理返回 HTTP 200 + body `code=500`，Feign 调用方会把它当“成功响应”反序列化 | 已证实设计后果 | 接口契约、服务调用 |
| 3 | 降级返回 `id=-1` / `code=1001`，V5 未识别，会拿降级数据继续建单 | 已证实（版本对比） | 服务调用 |
| 4 | `snowflake.properties` 的 `dc/machine` 未被实体使用，实体固定用 `(1,1)` | 已证实缺陷 | 分布式ID |
| 5 | `SnowFlakeFactoryTest` 把 `DataCenterId` 当 `MachineId` 传入 | 已证实缺陷 | 分布式ID |
| 6 | `20220412/shop.sql` 无 `undo_log`，Seata AT 回滚所需表不在正式迁移脚本中 | 已证实缺口 | 分布式事务 |
| 7 | `RocketMQTemplate.convertAndSend` 在数据库事务方法体内执行，且 `V8` 缺少 `@Transactional` | 潜在风险（按实现推导） | 消息服务、分布式事务 |
| 8 | `GatewayConfig` 用 `@Value` 强依赖 `route-id-prefix`，缺失即启动失败 | 潜在风险 | 服务网关 |
| 9 | `GlobalGatewayLogFilter` 打印的是“网关自身请求 URI 的 host/port”，不是被选中的后端实例 | 已证实语义错误 | 服务网关 |
| 10 | Sentinel 规则持久化写死 `server-order` 且为节点本地文件，多实例不一致 | 已证实局限 | 服务容错 |
| 11 | 多个 `application-*.yml` 与 Nacos 中的 `server-gateway-dev.yaml` 存在重复、注释、覆盖关系 | 已证实（配置漂移） | 服务网关、服务配置 |
| 12 | `ProductController.updateCount` 不校验库存，SQL 无 `stock >= count` 条件，可超卖为负 | 已证实缺陷 | 分布式事务 |

## 跨篇主题地图

- **失败模型**：超时（Feign 未配）、降级（哨兵值）、限流（BlockException）、回滚（Seata）、重复投递（MQ）、时钟回拨（雪花）——分散在各篇“踩坑”表，可汇总为一张全链路失败清单。
- **配置漂移**：本地 `application-*.yml`、Nacos 导出 zip、`bootstrap.yml` 三处来源并存，生产真实值不可从仓库唯一确定。
- **可观测性**：仅有 Sleuth/Zipkin 与零散 `log.info`；限流/降级/消息/事务均无指标埋点。
- **契约演进**：HTTP 接口既被 Feign 消费、又被 `bhrpc` 的 `@RpcReference` 消费（`shop-service-api` 接口），属于双栈并行的过渡形态。

## 阅读建议

1. **先读契约层**：接口契约 → 服务治理 → 服务调用 → 服务容错 → 服务网关。这五篇构成一次请求从入口到下游的完整链路。
