# 10 语音合成：对白抽取与角色音色匹配

> 标签：TTS / 文本解析 / 角色映射 / 多厂商音色

---

## 1. 场景与边界

剧本是一段结构化/半结构化的文本，包含旁白与角色对白。要合成配音，必须先：

1. **从剧本正文抽取对白行**（区分旁白 vs 角色台词）；
2. **给每个角色匹配音色**（查 `t_tts_config`，精确按 characterId，再模糊按角色名）；
3. 逐行调 TTS 厂商合成音频，落库并上传 OSS。

边界：本场景讲抽取与匹配；厂商 Provider 见第 02 篇，存储见第 08 篇。

---

## 2. 约束与难点

| 难点 | 说明 |
| --- | --- |
| 对白格式不统一 | 可能用 `:` 或 `：`，还可能是 `【角色】` 形式 |
| 旁白无角色 | 旁白需区分处理或走默认音色 |
| 角色名与配置不一致 | 剧本里是别名，配置里是全名，需模糊匹配 |
| 无配置兜底 | 未匹配到音色要能用默认音色，不中断 |
| 逐行合成为串行 | 多角色多行时耗时线性增长 |

---

## 3. 实现链路

### 3.1 抽取

```
extractDialogues(scriptContent)
  for each line:
     支持 【角色】形式 → characterName = tag
     否则用 DLG = ^(.+?)[:：](.+)$ 匹配 "角色:台词"
       matches → characterName = group(1), text = group(2)
       no match → narration = true
```

### 3.2 匹配

```
matchVoices(projectId, dialogues)
  configs = t_tts_config where projectId
  configByCharId: characterId → config ; defaultConfig = characterId 为空的
  for each dialogue:
      按 name 精确匹配 → config
      否则遍历 assets（角色资产）模糊匹配 name → characterId → config
      否则 defaultConfig
```

## 4. 关键选型与权衡

| 选择 | 理由 | 代价 |
| --- | --- | --- |
| 正则抽取对白 | 简单、无需 NLP | 格式一变即失效；复杂剧本易误判 |
| 精确 + 模糊匹配 | 提高命中率 | 模糊匹配可能错配 |
| 默认音色兜底 | 不中断生成 | 未配置角色音色不理想 |
| 逐行串行合成 | 实现简单 | 慢；大量对白时需并发 |
| 单行异常隔离 | 一行失败不影响整体 | 可能静默缺失若干行 |

---

## 5. 关键工程实现

**（1）对白正则（`TtsService.java:43,74-76`）**：`^(.+?)[:：](.+)$` 非贪婪匹配冒号前为角色、后为台词，同时兼容中英文冒号。【代码事实】

**（2）音色匹配三级（`TtsService.java:101-141`）**：`characterId` 精确 → 角色名经 assets 模糊 → 默认配置。【代码事实】

**（3）失败隔离（`TtsService.java:209`）**：单行合成异常只记录日志，不抛出，保证整批继续。【代码事实】

## 6. 踩坑根因排障

| 现象 | 根因 | 排查/处理 |
| --- | --- | --- |
| 对白一条都没抽到 | 剧本格式与正则不符 | 对照 `DLG`，或扩展抽取规则 |
| 旁白被当成角色 | 行内有冒号 | 需更严格的角色识别（如结合角色名单） |
| 某角色用了默认音色 | 名称与 `TtsConfig`/资产不一致 | 检查模糊匹配与角色资产 |
| 音频缺失若干条 | 单行合成失败被吞 | 查看 `[TTS] Failed for character=` 日志 |
| 合成特别慢 | 逐行串行 | 改为有界并发 |
| 音色列表为空 | `manufacturer` 过滤不匹配 | 对照 `getVoices` 内的制造商取值 |

## 7. 可迁移落地方案

`【落地建议】`

1. **抽取与合成解耦**：先产出结构化 `DialogueLine[]`，再做音色匹配与合成，便于单测与替换。
2. **角色识别增强**：不要只靠冒号；结合「已知角色名集合」做精确/模糊匹配，减少误判。
3. **匹配优先级**：`characterId 精确 → 名称精确 → 名称模糊 → 项目默认 → 全局默认`。
4. **失败不静默**：失败的对话行要记录并在结果中标记，便于重试。
5. **并发合成**：用有界线程池并发合成，注意厂商限流。
6. **音色注册表**：把可用音色做成可查询的注册表（按厂商），前端可直接选用。

## 8. 替代方案与适用边界

| 方案 | 适用 | 不适用 |
| --- | --- | --- |
| 正则抽取（本方案） | 格式规整的剧本 | 自由文本 |
| LLM 结构化抽取 | 格式多样、需语义 | 成本高 |
| 剧本结构化存储 | 从源头就有角色/台词字段 | 需上游改造 |
| 流式 TTS | 实时对话场景 | 批量配音 |
