# 08 对象存储：服务端中转上传与未配置降级

> 标签：对象存储 / S3 / MinIO / 降级 / 配置治理

---

## 1. 场景与边界

平台产生大量二进制产物：素材、资产图、分镜图、TTS 音频、视频、合成成片。统一通过服务端封装的 `OssService`（基于 AWS S3 SDK）写入对象存储，兼容 S3 协议（AWS S3 / MinIO / 各家兼容存储）。

工程问题：
1. **统一出口**：所有上传/删除走一个 Service，避免各业务各写一套；
2. **未配置可降级**：本地开发通常没有 OSS，应用要能**不报错地跑起来**；
3. **URL ↔ key 互转**：删除时要从完整 URL 反解出对象 key。

边界：本场景讲存储封装；视频产物落库见第 04 篇。

---

## 2. 约束与难点

| 难点 | 说明 |
| --- | --- |
| 未配置 OSS 时不能启动失败 | 用 `@PostConstruct` 探测，未配置则禁用 |
| 上传失败不能阻断业务 | 捕获异常返回占位路径 |
| 兼容多后端 | 用 S3 SDK + `endpointOverride` 兼容 MinIO |
| URL 反解 key | 需从 `base-url`/endpoint 剥离前缀 |
| 配置键易错 | 前缀不一致会导致配置静默失效 |

---

## 3. 实现链路

### 3.1 初始化与降级

```
@PostConstruct init()
  if (accessKey/secretKey 为空) → log.warn + return（enabled=false）
  else 构建 S3Client（可 endpointOverride）→ enabled=true
  catch → log.warn，保持 enabled=false

upload(key, bytes, contentType)
  if (!enabled) → log.warn + return "/" + key      # 占位路径，不报错
  try putObject → resolveUrl(key)
  catch → log.error + return "/" + key             # 失败同样降级
```

## 4. 关键选型与权衡

| 选择 | 理由 | 代价 |
| --- | --- | --- |
| 服务端中转上传 | 前端无需持有密钥，权限可控 | 占用服务端带宽与内存 |
| 未配置即禁用（非报错） | 本地开发零依赖即可跑 | 生产若忘配会「以为上传成功」实为占位路径 |
| 失败返回占位路径 | 不阻断业务 | 静默失败，需靠日志发现 |
| S3 SDK 兼容 MinIO | 一套代码多后端 | `Region` 硬编码需注意 |

---

## 5. 关键工程实现

**（1）初始化守卫（`OssService.java:46-64`）**：缺凭证就 `log.warn` 并保持 disabled，应用照常启动。【代码事实】

**（2）上传双重降级（`OssService.java:70-89`）**
```java
if (!enabled || s3Client == null) return "/" + key;   // 未配置
try { s3Client.putObject(...); return resolveUrl(key); }
catch (Exception e) { return "/" + key; }             // 调用失败
```
`【工程推断】` 调用方拿到 `/xxx` 时要能识别这是「本地占位」而非真实 URL。

**（3）删除需反解 key（`MaterialService.java:70`）**：`ossService.extractKey(material.getFilePath())` 后再删。【代码事实】

## 6. 踩坑根因排障

| 现象 | 根因 | 排查/处理 |
| --- | --- | --- |
| **配了 OSS 却不生效** | `OssService` 读 `story.oss.*`，yml 是 `video.oss.*` | 统一前缀（本项目已知不一致）`OssService.java:28-40` vs `application.yml:47-51` |
| 上传「成功」但文件不存在 | 未配置/失败降级返回 `"/"+key` | 检查 `enabled` 与日志 `[OSS] OSS not enabled` |
| MinIO 报区域错误 | `Region.AP_EAST_1` 硬编码 | MinIO 可忽略或改配置 |
| 删除删不掉 | URL 前缀与 `base-url` 不一致导致 `extractKey` 解析错误 | 核对 `extractKey` 逻辑与 `base-url` |
| 生产环境占位路径污染数据 | 未配置却在生产运行 | 启动时对生产 profile 强制校验 OSS 必配 |

## 7. 可迁移落地方案

`【落地建议】`

1. **单一存储出口**：一个 `ObjectStorageService` 接口 + S3 实现，业务只依赖接口。
2. **启动探测 + 禁用降级**：本地无凭证时禁用并警告，**生产 profile 下改为启动失败**（fail-fast），避免静默降级。
3. **返回结构化结果**：不要只返回字符串，返回 `{url, storageKey, stored: boolean}`，让调用方知道是否真实落盘。
4. **URL↔key 规范化**：上传后返回的 URL 与删除时反解必须用同一套 `base-url` 规则。
5. **配置统一前缀 + 校验**：全项目用同一顶层键，并用 `@ConfigurationProperties` + `@Validated` 约束。
6. **直传可选**：大文件可用预签名 URL 让前端直传，减轻服务端压力。

---

## 8. 替代方案与适用边界

| 方案 | 适用 | 不适用 |
| --- | --- | --- |
| 服务端中转 S3 SDK（本方案） | 中小文件、权限集中 | 超大文件、高并发 |
| 前端预签名直传 | 大文件、减轻服务端 | 需要签名服务 |
| 云厂商 SDK（OSS/COS） | 特定云深度集成 | 多云 |
| 本地磁盘 | 单机、开发 | 分布式 |

## 9. 验收清单

- [ ] 未配置 OSS 时应用可启动且上传返回占位路径并有警告日志。
- [ ] 配置正确时上传成功并返回可访问 URL。
- [ ] 上传失败不抛异常、返回占位路径并记录错误。
- [ ] `extractKey` 能从上传返回的 URL 正确反解 key。
- [ ] 配置前缀与 `application.yml` 一致（核对 `story.*`/`video.*`）。
- [ ] 生产环境对缺失 OSS 配置 fail-fast（建议补齐）。
