# 08 对象存储：服务端中转上传与未配置降级

> 标签：对象存储 / S3 兼容 / 文件上传 / 优雅降级 / 配置治理
>
> 证据根：`story-video-service/src/main/java/io/binghe/framework/service/{OssService,MaterialService}.java`

---

## 1. 场景与边界

短剧生成了大量媒体文件：素材（BGM/音效/片头片尾/水印）、角色资产图、分镜图、TTS 音频、成片。这些文件不能放进数据库，需要对象存储（S3/OSS/MinIO）。

工程问题：

1. **统一存储抽象**：一套代码对接 S3 兼容的多种后端；
2. **上传路径**：浏览器直传（预签名）还是服务端中转？路径怎么组织？
3. **未配置时不能崩**：开发/演示环境常常没配 OSS，业务不能因此 500；
4. **URL ↔ key 可逆**：保存的是可访问 URL，删除时要能从 URL 反推 key；
5. **删除一致性**：删素材时也要删对象。

边界：
- 本文聚焦「服务端中转上传 + 未配置降级 + URL/key 转换」。
- 素材上传入口见 `MaterialController`；TTS/图片/视频生成中的上传调用分散在各 Service（第 04/10 篇）。
- 配置前缀问题（§6.1）属**代码事实**，其「配置是否从别处注入」列入 §10 待确认。

---

## 2. 约束与难点

| 难点 | 说明 |
| --- | --- |
| 多后端差异 | S3/OSS/MinIO 端点和 region 不同，需 `endpointOverride` |
| 未配置降级 | 没有凭据时要「能用但用不了真存储」，而不是启动失败 |
| URL 可逆 | 保存 `filePath` 为完整 URL，删除时需 `extractKey` |
| 内容类型 | 不同扩展名要正确 `Content-Type`，否则浏览器行为异常 |
| key 唯一 | 同名文件不能覆盖，需要 UUID |
| 大文件 | 服务端中转会把整个文件读进内存（`MultipartFile.getBytes()`） |

## 3. 实现链路

### 3.1 初始化：按凭据决定是否启用

```
@PostConstruct init()
  ├─ accessKey/secretKey 任一为空 → log.warn("Access key not configured, OSS upload will be disabled")，enabled=false，直接 return
  ├─ 否则构建 S3Client：StaticCredentialsProvider + Region.AP_EAST_1
  │     endpoint 非空 → builder.endpointOverride(URI.create(endpoint))
  └─ enabled=true，log.info("S3 client initialized, bucket=...")
  （初始化异常 → log.warn，保持 enabled=false）
```

### 3.2 上传 / 删除 / 提取 key

| 操作 | 逻辑 |
| --- | --- |
| `upload(key, data, contentType)` | 未启用 → 返回 `"/" + key`；否则 `putObject`，成功返回 `resolveUrl(key)`，异常也返回 `"/" + key` |
| `delete(key)` | 未启用/key 空 → 直接返回；否则 `deleteObject`，异常仅 warn |
| `extractKey(url)` | 若 url 以 `baseUrl` 开头 → 去掉 baseUrl；否则去掉开头 `/` |
| `resolveUrl(key)` | 有 baseUrl → `baseUrl + "/" + key`；否则有 endpoint → `endpoint + "/" + bucket + "/" + key`；否则 `"/" + key` |

### 3.3 素材上传（`MaterialService.upload`）

```
ext = extractExt(originalFilename)           // 取扩展名，小写，无扩展名返回 ""
key = "materials/" + type + "/" + UUID + ext // 路径按类型分目录 + UUID 防覆盖
contentType = resolveContentType(ext)        // mp3/wav/aac/mp4/png/jpg → 对应 MIME，默认 octet-stream
filePath = ossService.upload(key, bytes, contentType)
insert Material{name,type,category,userId,filePath}
```

删除：`selectById` → 不存在抛 `NOT_FOUND` → `extractKey(filePath)` → `ossService.delete(key)` → `deleteById`。

## 4. 关键选型与权衡

| 选择 | 理由 | 代价 |
| --- | --- | --- |
| AWS S3 SDK 对接 S3 兼容存储 | 一套 SDK 通吃 MinIO/OSS/S3 | 需 `endpointOverride` + 固定 region 技巧 |
| 服务端中转上传 | 前端简单、可服务端校验 | 带宽/内存占用在服务端 |
| 未配置降级返回占位路径 | 开发期不崩 | **静默降级**，生产误配不易发现（见 §6.1） |
| URL 即 `filePath` | 前端直接用 | 需 `extractKey` 反推，且 baseUrl 变化会破坏映射 |
| key 用 UUID | 防覆盖 | 丢失可读性（按 type 分目录部分弥补） |
| `enabled` 布尔控制 | 简单 | 无「半可用」状态 |

## 5. 关键工程实现

**（1）初始化与降级开关（`OssService.java:45-65`）**

```java
@PostConstruct
public void init() {
    if (accessKey == null || accessKey.isBlank() || secretKey == null || secretKey.isBlank()) {
        log.warn("[OSS] Access key not configured, OSS upload will be disabled");
        return;                                    // enabled 保持 false
    }
    try {
        var builder = S3Client.builder()
                .credentialsProvider(StaticCredentialsProvider.create(AwsBasicCredentials.create(accessKey, secretKey)))
                .region(Region.AP_EAST_1);
        if (endpoint != null && !endpoint.isBlank()) builder.endpointOverride(URI.create(endpoint));
        s3Client = builder.build();
        enabled = true;
    } catch (Exception e) { log.warn("[OSS] Failed to initialize S3 client: {}", e.getMessage()); }
}
```

**（2）上传降级（`OssService.java:70-90`）**

```java
public String upload(String key, byte[] data, String contentType) {
    if (!enabled || s3Client == null) {
        log.warn("[OSS] OSS not enabled, returning placeholder path for key={}", key);
        return "/" + key;                          // 占位路径，不抛错
    }
    try {
        s3Client.putObject(PutObjectRequest.builder().bucket(bucket).key(key).contentType(contentType).build(),
                           RequestBody.fromBytes(data));
        return resolveUrl(key);
    } catch (Exception e) {
        log.error("[OSS] Upload failed for key={}: {}", key, e.getMessage());
        return "/" + key;                          // 失败同样降级
    }
}
```

**（3）URL 与 key 互转（`OssService.java:109-128`）**：`resolveUrl` 三级回退，`extractKey` 反向剥离。

**（4）素材 key 组织（`MaterialService.java:47-51`）**

```java
String ext = extractExt(originalFilename);
String key = "materials/" + type + "/" + UUID.randomUUID() + ext;
String contentType = resolveContentType(ext);
String filePath = ossService.upload(key, fileBytes, contentType);
```

## 6. 踩坑根因排障

### 6.1 【代码事实】配置前缀不匹配 → 默认永久降级

`OssService` 读的是 **`story.oss.*`**：

```java
@Value("${story.oss.endpoint:}")   private String endpoint;
@Value("${story.oss.access-key:}") private String accessKey;
@Value("${story.oss.secret-key:}") private String secretKey;
@Value("${story.oss.bucket:story}") private String bucket;
@Value("${story.oss.base-url:}")   private String baseUrl;
```

而 `application.yml` 配的是 **`video.oss.*`**（`application.yml:47-51`，bucket 默认 `binghe`）。

**后果**：`story.oss.access-key` 永远取不到值 → `accessKey` 为空 → `init()` 直接禁用 → 所有 `upload` 都返回 `"/" + key` 占位路径。**即默认配置下 OSS 从未真正启用**，上传的文件既没进对象存储，前端拿到的也是本地相对路径。且 `video.oss.bucket=binghe` 也被忽略（用的是 `story.oss.bucket` 默认 `story`）。

**排查**：看启动日志有没有 `[OSS] Access key not configured`。**修复**：统一前缀（改 `@Value` 为 `video.oss.*`，或把 yml 改成 `story.oss.*`），并补 `base-url` 配置项。

### 6.2 【代码事实】降级是「静默」的，生产误配不易察觉

`upload` 在未启用和异常时都返回 `"/" + key`，调用方（TTS/图片/视频）会把占位路径当正常 URL 存库。**没有异常、没有特殊标记**，只有一行 warn 日志。生产环境误配 OSS 时，表现为「图片/音频 URL 打不开」，而非明确报错。

**建议**：降级时返回带明显标识的 URL（如 `placeholder://...`），或在响应中带 `storageEnabled=false`，让上层可感知。

### 6.3 【代码事实】`Region` 硬编码 `AP_EAST_1`

所有后端（包括非 AWS 的 MinIO/OSS）都被固定成 `ap-east-1`。用 `endpointOverride` 时多数兼容存储会忽略 region，但个别后端（尤其带 SigV4 校验）可能因 region 不匹配而签名失败。建议把 region 也做成配置项。

### 6.4 【代码事实】素材上传的 `userId` 来自请求参数，可伪造

```java
@RequestParam(required = false) Long userId
...
materialService.upload(file.getBytes(), file.getOriginalFilename(), name, type, category, userId);
```
`userId` 由**客户端传入**，而非从安全上下文（`SecurityUtil.getCurrentUserId()`）取。任何登录用户可以伪造成别人上传素材。其它 Service（如 `VideoService`）用的是 `SecurityUtil`，此处不一致。

### 6.5 【代码事实】服务端全量读入内存

`MaterialController` 调 `file.getBytes()`，`MaterialService` 调 `RequestBody.fromBytes(data)`：**整个文件驻留 JVM 内存**。大视频/大音频素材（几十 MB～上百 MB）并发上传会显著抬高堆占用，甚至 OOM。建议直传（预签名 URL）或流式上传。

### 6.6 【代码事实】删除不校验归属

`MaterialService.delete(id)` 只按 id 删除，**不校验该素材是否属于当前用户**。配合 §6.4 的伪造 userId，越权删除风险成立。

### 6.7 【代码事实】`extractKey` 依赖 `baseUrl` 一致性

若某天 `baseUrl` 配置变更（或从「endpoint+bucket」切换到「baseUrl」），历史数据里存的 URL 前缀与新 `resolveBaseUrl()` 不再匹配 → `extractKey` 会退化为「只去掉开头 `/`」，得到一坨带域名的错误 key → 删除删不掉对象。URL 与 key 的映射对配置变更不健壮。

### 6.8 常见现象对照表

| 现象 | 根因 | 排查/处理 |
| --- | --- | --- |
| 上传后文件打不开、返回 `/materials/...` | OSS 未启用/前缀不匹配（§6.1） | 看 `Access key not configured`；统一前缀 |
| 生产上文件丢失但无报错 | 静默降级（§6.2） | 让降级显式化 |
| 签名校验失败(SignatureDoesNotMatch) | region 硬编码（§6.3） | region 配置化 |
| 素材归属/删除越权 | userId 可伪造 + 删除不校验（§6.4/§6.6） | 用 `SecurityUtil` + 归属校验 |
| 上传大文件 OOM | 全量入内存（§6.5） | 改预签名直传/流式 |
| 改了域名后删除删不掉 | `extractKey` 依赖 baseUrl（§6.7） | 存 key 而非 URL，或做兼容映射 |
| Content-Type 不对 | 扩展名不在映射表 | 扩充 `resolveContentType` |

## 7. 可迁移落地方案

`【落地建议】`

1. **配置前缀统一 + 启动自检**：所有组件读同一前缀；启动时若关键配置缺失，除 warn 外应在健康检查/就绪探针里暴露「存储不可用」。
2. **降级要可感知**：返回明确的占位标识或状态字段，别让占位路径冒充真 URL。
3. **存 key、不存 URL**：数据库保存对象 key（或 `bucket + key`），访问 URL 由「baseUrl + key」在读取时拼装。这样换域名/换厂商都不影响数据。
4. **大文件走上直传**：服务端签发预签名 URL，浏览器直传对象存储；小文件再考虑中转。
5. **上传参数中的身份一律从安全上下文取**：`userId`、租户 id 绝不信任客户端。
6. **删除要校验归属**：按 `id + userId` 双条件查询后再删。
7. **存储抽象接口化**：把 `put/delete/url` 抽成 `StorageService` 接口，S3/MinIO/本地实现可切换，避免业务直接依赖 SDK。

## 8. 替代方案与适用边界

| 方案 | 适用 | 不适用 |
| --- | --- | --- |
| 服务端中转 + S3 SDK（本方案） | 小文件、需服务端处理 | 大文件、高并发 |
| 前端预签名直传 | 大文件、降服务端压力 | 需额外签名接口与前端配合 |
| 分片上传/断点续传 | 超大文件、弱网 | 实现复杂 |
| 本地磁盘 + Nginx | 单机、演示 | 多实例、持久化要求 |
| 专业 SDK（Aliyun OSS SDK / MinIO SDK） | 需要厂商高级特性 | 锁定厂商 |
